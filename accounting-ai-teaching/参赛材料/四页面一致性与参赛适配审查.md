# 四页面一致性与参赛适配审查

审查对象：

1. 应用A学生端：大学生生活记账与会计AI伴学
2. 应用A教师端：班级会计认知地图
3. 应用B学生端：校园数字支付与会计AI推演
4. 应用B教师端：数字支付实验教学驾驶舱

## 一、四页面统一定位

统一教学原则：

> 知识模型化、练习游戏化、评价数据化、教学智能化。

统一人机边界：

> 学生先作首次判断；规则处理确定性问题；AI负责结构化、追问、反馈与变式；教师保留最终评价权。

统一证据链：

```text
学生首次判断
→规则/AI发现问题
→学生订正
→变式迁移
→过程数据入库
→教师诊断
→教师复核与备课
```

## 二、应用A学生端

### 页面任务

把生活事项转化为会计学习材料，重点解决：会计主体、现金与收入费用混淆、债权债务遗漏、会计等式机械判断。

### 正确结构

```text
首页入口
→隐私模式
→记录一项事项
→输入质量检查
→AI结构化（不抢答）
→学生首次判断
→追问与订正
→变式迁移
→最近学习卡
```

首页七个入口：

1. 记录一笔/模拟事项
2. 3D会计等式实验
3. 生活经济关系剧场
4. 本阶段练习推荐
5. 校园经济生活图谱
6. 全部生活情境
7. 最近学习卡

### 参赛亮点

- 真实、模糊、模拟三种记录模式，避免隐私换分。
- AI不在首次判断前给答案。
- 生活事项与企业会计之间设置主体辨析和迁移边界。
- 3D等式、双主体关系、小游戏结果均可进入教师端。

## 三、应用A教师端

### 页面任务

不是展示单一成绩，而是呈现班级认知问题、学生订正轨迹和教师最终复核。

### 正确结构

```text
顶部教学洞察
→核心实时/样例指标
→30秒人机协同闭环
→班级与账号
→学生个体轨迹
→班级认知地图
→双主体/等式/游戏分析
→AI备课
→教师复核
```

### 数据口径

- 数据库实时指标：参与人数、记录数、订正数量等。
- 尚未取得真实试用结果的指标必须明确标注“演示班样例指标”。
- 正式参赛视频不得把演示数据表述成真实教学成效。

## 四、应用B学生端

### 页面任务

让不可见的数字支付关系和时间差异可视化，重点解决箭头方向、权利义务、购买与付款时点、平台多方结算。

### 正确结构

```text
场景大厅
→空间推演入口
→精选实验
→全部实验
→选择时间节点
→建立关系箭头
→首次预测
→规则/AI反馈
→订正与会计要素迁移
→保存推演
```

### 手势边界

- 3D空间实验属于“本地手势识别”，不是严格意义上的AR。
- 手势闯关只使用稳定、统一的主体选择映射：
  - ☝校园商家
  - ✌学生
  - 👍信用支付方
- 商品交付和资金支付动作留在独立手势体验区，不与主体知识题混用。
- 所有摄像头功能必须有按钮备选。

## 五、应用B教师端

### 页面任务

从场景、箭头、关系、时间节点和会计要素五个维度诊断学生推演过程。

### 正确结构

```text
顶部实验洞察
→核心数据
→30秒人机协同闭环
→班级与账号
→学生推演轨迹
→场景效果
→关系错误
→时间节点诊断
→手势闯关统计
→AI备课
→教师复核
```

## 六、四页面一致性检查结论

| 检查项 | 结论 |
|---|---|
| 学生先判断、AI后反馈 | 一致 |
| 教师最终评价权 | 一致 |
| 学生端结果进入教师端 | 一致 |
| 摄像头本地处理与按钮备选 | 一致 |
| 首页说明弹窗与聚光灯 | 已统一 |
| 教师端先讲顶部总览再向下滚动 | 已统一 |
| 3D/手势术语 | 已统一，删除不严谨AR表述 |
| 演示数据与真实数据口径 | 已增加样例标识，真实试用后替换 |
| 隐私保护 | 应用A完整；应用B摄像头本地处理 |
| 鼠标/触屏回退 | 保留 |

## 七、参赛前必须完成

1. 暑期邀请2—3名同行教师完成教学逻辑与可用性走查，不将其表述为学生教学效果。
2. 教师端继续明确区分SQLite实时记录与演示班样例指标。
3. 2026年秋季学期再开展5—10名学生的小规模正式应用验证，并据实补充效果数据。
4. 录制时明确展示“首次判断—AI追问—学生订正—教师复核”。
5. 不把本地手势识别称为AR。
6. 摄像头演示使用localhost或HTTPS；同时演示按钮备选。
7. 演示账号、在线地址、本机包和视频必须互为备份。

