# 参赛演示验收清单

## 一、安装和启动

- [ ] 在全新文件夹执行 `setup-first-time.cmd` 成功
- [ ] `start-app-a.cmd` 在健康检查通过后打开3000端口
- [ ] `start-app-b.cmd` 在健康检查通过后打开3001端口
- [ ] `verify-running.cmd` 两个应用均显示 `ok:true`
- [ ] 断网时Mock模式仍可完成核心流程
- [ ] Windows防火墙允许Node.js专用网络访问

## 二、演示账号

- [ ] 一键进入学生演示可用
- [ ] 一键进入教师演示可用
- [ ] 当前账号和角色始终显示
- [ ] 学生不能进入教师端
- [ ] 教师创建试用账号并导出CSV可用

## 三、应用A三分钟流程

- [ ] 选择校园卡或垫付情境
- [ ] 输入质量检查可发现模糊、多事项和金额冲突
- [ ] AI或离线规则完成结构化
- [ ] 学生完成结构化判断和理由
- [ ] 保存首次判断到SQLite
- [ ] 完成订正并查看首次/订正对照
- [ ] 教师端能找到该学生记录
- [ ] 认知地图、AI复核和CSV导出可用

## 四、应用B三分钟流程

- [ ] 选择校园卡或花呗实验
- [ ] 节点可拖动，关系可连接和删除
- [ ] 时间节点可切换并分别保存
- [ ] 会计要素5项完成提示清楚
- [ ] 分数构成和提分建议清楚
- [ ] 进入订正模式后必须实际修改
- [ ] 首次/订正推演对照可见
- [ ] 教师端能查看场景数据和学生轨迹

## 五、3D与手势

- [ ] 3D模型使用人物、门店和信用支付形象
- [ ] 商品包裹、资金与契约关系动画方向清楚
- [ ] 应用B主体手势映射清楚：☝商家、✌学生、👍信用支付方
- [ ] 应用A判断手势映射清楚：☝左、✌右、👍是、✊否
- [ ] 手势闯关可用摄像头或按钮完成
- [ ] 闯关分数写入SQLite
- [ ] 教师端能查看手势正确率
- [ ] 摄像头失败时鼠标模式仍可完整演示

## 六、四个设计支柱

- [ ] 模型化：2D/3D关系与时间截面可展示
- [ ] 游戏化：关系推演、变式和手势闯关可展示
- [ ] 数据化：学生轨迹、热力图、复核和成绩可展示
- [ ] 智能化：DeepSeek伴学、AI备课和资源推荐可展示

## 七、按钮和界面

- [ ] 运行 `npm run audit:ui` 通过
- [ ] 所有主按钮均可点击并有反馈
- [ ] 聚光灯说明框明亮且可操作
- [ ] 学生和教师导航固定或可快速返回
- [ ] 手机、电脑和平板关键流程无明显遮挡

## 八、数据与安全

- [ ] 演示前运行 `backup-data.cmd`
- [ ] 源码包中不含真实API Key
- [ ] 教师只看到脱敏摘要
- [ ] 摄像头视频不上传、不保存
- [ ] DeepSeek失败时自动降级

## 九、发布检查

在项目根目录运行：

```bash
npm run check:release
```

或双击：

```text
release-check.cmd
```

必须看到：

```text
RELEASE CHECK PASSED
```

## 十、视频口径与成片检查

- [ ] 常规项目主视频只围绕应用A，不混入应用B造成作品边界不清
- [ ] 解说明确“学生先判断、AI后反馈、教师终审”
- [ ] 演示指标明确称为样例，不冒充真实教学效果
- [ ] 不使用“AR”描述当前3D＋手势功能
- [ ] 不宣称AI自动决定最终成绩
- [ ] 不展示真实学生姓名、消费明细或API Key
- [ ] 成片控制在平台要求时长内，字幕和鼠标轨迹清晰
