# 正式录制操作手册

适用作品：大学生生活记账与会计AI伴学软件  
建议成片：4分50秒—5分00秒  
建议录制方式：分段录屏＋后期旁白，不建议一次性边操作边讲解。

---

# 一、录制前一天必须准备

## 1. 确定视频边界

常规项目主视频只展示应用A：

> 大学生生活记账与会计AI伴学软件

应用B不要混入主视频。应用B另录辅助视频。

主视频只保留六段：

1. 教学问题与作品来源；
2. 学生端“记录一笔”完整闭环；
3. 3D会计等式实验；
4. 双主体关系与简单手势判断；
5. 教师认知地图和人机协同复核；
6. AI备课、隐私与总结。

## 2. 建立录制文件夹

建议在非项目目录创建：

```text
参赛视频录制/
├── 01_原始录屏/
├── 02_旁白录音/
├── 03_截图素材/
├── 04_字幕与文案/
├── 05_剪辑工程/
├── 06_导出预览/
└── 07_最终成片/
```

原始文件不要直接覆盖。每次重录使用新编号。

## 3. 准备画面素材

需要提前准备：

- 企业微信原始作业的匿名截图；
- 至少3条典型错误，但必须删除姓名、头像、班级和个人消费细节；
- 作品名称页；
- “知识模型化、练习游戏化、评价数据化、教学智能化”四支柱图；
- “学生先判断—AI后反馈—教师终审”流程图；
- 作品结束页；
- 作者和单位信息（最终确认后再加入）。

匿名截图建议只保留：

```text
买东西
收到转账
花呗付款
替同学垫付
会计要素：支出/资金
```

不要保留：

- 学生真实姓名；
- 头像；
- 手机号；
- 微信号；
- 家庭情况；
- 具体商家和敏感消费；
- 班级群名称。

## 4. 准备演示数据

主演示建议固定使用“垫付与收回”：

```text
我替三位同学先付了200元聚餐费，他们之后归还。
```

准备状态：

- 学生账号可以正常登录；
- 表单可以直接使用模拟事项；
- 首次判断尚未完成，便于从头录制；
- 教师端已经有若干匿名演示记录；
- 至少有一条待教师复核记录；
- 至少有一条教师退回后学生重新提交的演示轨迹；
- 3D等式、双主体关系、游戏结果有演示数据；
- 教师端样例百分比显示“演示班样例指标”。

正式录制前先运行：

```text
backup-data.cmd
```

记录备份文件名和时间。录制过程中不要运行：

```text
db:setup
reset-demo-data.bat
```

这两个操作会重置本机数据。

## 5. 确定AI模式

### 主方案：在线DeepSeek

录制前检查：

1. 已执行`configure-deepseek.cmd`；
2. `.env.local`中的模型为`deepseek-v4-flash`；
3. API余额和网络正常；
4. 关闭并重新启动应用；
5. AI状态面板显示在线；
6. 提前完整运行一次“垫付与收回”；
7. 确认响应时间和反馈内容适合录制。

### 备份方案：Mock模式

提前测试：

```text
use-mock-ai.cmd
```

Mock模式也必须能完成：

- 结构化；
- 首次判断；
- 追问；
- 订正；
- 教师复核。

绝对不要录制API Key输入过程，也不要打开`.env.local`。

# 二、电脑与录屏环境

## 1. 推荐设备

- Windows 10/11电脑；
- 16GB内存优先，最低8GB；
- 1920×1080或更高分辨率；
- 鼠标，不建议只用触控板；
- 独立麦克风或质量较好的耳麦；
- 如录手势，准备可正常工作的摄像头。

笔记本录制时连接电源，并关闭省电模式。

## 2. 显示设置

建议：

```text
桌面分辨率：1920×1080
Windows缩放：100%或125%
浏览器缩放：100%
浏览器：最新版Edge或Chrome
```

如果界面内容太小，优先调整Windows缩放或浏览器窗口，不要在录制中频繁缩放。

关闭：

- 浏览器书签栏；
- 下载栏；
- 开发者工具；
- 无关标签页；
- 微信、QQ、企业微信通知；
- 邮件通知；
- 杀毒软件弹窗；
- Windows更新提示；
- 输入法状态提示；
- 桌面无关文件和私人壁纸。

开启Windows“专注助手”或“勿扰模式”。

## 3. 浏览器准备

建议准备两个独立浏览器窗口或两个浏览器配置：

```text
窗口A：学生端
窗口B：教师端
```

但两个应用共享会话Cookie时，同一浏览器同时切换角色可能相互影响。最稳妥方案：

- Edge普通窗口登录学生；
- Chrome登录教师；

或者：

- Chrome普通窗口登录学生；
- Edge普通窗口登录教师。

不要依赖同一浏览器的两个标签页同时保持不同角色。

## 4. 推荐录屏软件

建议使用OBS Studio。

OBS基础设置：

```text
画布分辨率：1920×1080
输出分辨率：1920×1080
帧率：30fps
录制格式：MKV
编码器：硬件H.264（如可用）
质量：高质量，中等文件大小
```

先录MKV，录完在OBS中转换为MP4。MKV在软件崩溃时不容易损坏整个文件。

如果平台最终要求MP4，导出建议：

```text
编码：H.264
分辨率：1920×1080
帧率：30fps
视频码率：8—12Mbps
音频：AAC，48kHz，192—320kbps
```

不要录成4K，文件过大且没有必要。

## 5. OBS场景建议

建立以下场景：

```text
01_全屏浏览器
02_匿名作业截图
03_应用A学生端
04_应用A教师端
05_局部放大
06_结束页
```

录制网页时优先使用“窗口捕获”，避免录入桌面通知。如果窗口捕获出现黑屏，再使用“显示器捕获”。

鼠标指针必须录入。

# 三、声音准备

## 1. 最推荐方式

先录画面，后录旁白。

优点：

- 操作失误可以单独重录；
- AI等待时间可以剪切；
- 旁白节奏稳定；
- 不会因为口误导致整段返工；
- 可以精确控制5分钟时长。

## 2. 麦克风环境

- 关闭空调强风；
- 关闭电扇；
- 远离窗户和走廊；
- 手机调静音；
- 麦克风距离嘴部约15—20厘米；
- 不要正对麦克风吹气；
- 录制前喝水；
- 每段旁白前后留2秒静音。

## 3. 音量标准

建议旁白峰值保持在：

```text
-12dB至-6dB
```

不能爆音，也不能小到必须提高电脑音量才能听清。

背景音乐不是必需。若使用：

- 只能使用明确可商用或免版权音乐；
- 音量比旁白低18—25dB；
- 不要使用歌词音乐；
- 不要让音乐盖住中文辅音。

## 4. 解说语速

建议：

```text
每分钟220—260个汉字
```

五分钟旁白控制在约1000—1200字。重要术语稍停顿：

```text
首次判断｜AI追问｜学生订正｜教师复核
```

# 四、软件启动与录制前自检

## 1. 启动前

1. 重启电脑；
2. 连接电源；
3. 检查剩余磁盘空间不少于20GB；
4. 关闭无关软件；
5. 启动OBS但暂不录制；
6. 运行`start-app-a.cmd`；
7. 等待健康检查通过；
8. 浏览器访问`http://localhost:3000`。

## 2. 健康检查

打开：

```text
http://localhost:3000/api/health
```

应显示：

```json
{"ok":true,"database":"connected"}
```

## 3. 必测按钮

正式录制前逐项点击：

- 一键学生演示；
- 一键教师演示；
- 记录一笔；
- 使用模拟事项；
- 通过检查并让AI整理；
- 首次判断提交；
- 订正提交；
- 首次与订正对照；
- 3D等式实验；
- 关系剧场；
- 手势认知闯关；
- 教师端认知地图；
- 30秒复核演示；
- AI备课。

发现问题先修复，不要寄希望于后期遮盖。

## 4. 聚光灯检查

确认：

- 首次进入首页有说明弹窗；
- 首页聚光灯从顶部开始；
- 记录一笔聚光灯不会反复弹出；
- 3D等式先显示说明弹窗，再显示三步聚光灯；
- 关系剧场从案例选择开始；
- 教师端从顶部教学洞察开始，不直接跳到下半页；
- 点击“引导”可重新播放；
- 提示框不遮挡被讲解按钮。

如果本次浏览器会话已经看过弹窗，需要重新拍摄首次引导，可关闭所有浏览器窗口后重开；必要时清除该站点的会话存储。不要删除数据库。

# 五、分段录制清单

每段建议录两遍。第一遍保证完整，第二遍优化鼠标和节奏。

## 第1段：教学问题（建议25秒）

画面：匿名企业微信截图。

操作：

- 缓慢放大“买东西”“现金流入＝收入”“会计要素：支出”等典型问题；
- 不要快速晃动鼠标；
- 每个问题停留2—3秒。

文件名：

```text
A01_教学问题_01.mkv
```

## 第2段：首页与作品定位（建议20秒）

画面：应用A学生首页。

拍摄：

- 作品名称和首页主视觉；
- 记录一笔；
- 3D等式；
- 关系剧场；
- 本阶段练习推荐。

聚光灯只保留关键2步，不必完整录七步。

## 第3段：记录一笔核心闭环（建议65秒）

演示事项：

```text
我替三位同学先付了200元聚餐费，他们之后归还。
```

必须拍到：

1. 模拟记录；
2. 与事项的关系；
3. 垫付/收回类别；
4. 金额与支付方式；
5. 当前资金状态；
6. 输入质量检查通过；
7. AI结构化；
8. 学生首次判断；
9. 学生首次理由；
10. AI追问；
11. 订正理由；
12. 首次—订正对照。

不要在填写每个字段时停留太久。可以分别录制“输入”和“反馈”两小段，后期拼接。

## 第4段：3D会计等式（建议35秒）

优先选择：

```text
赊购原材料
```

原因：资产与负债同时增加，左右两盘都有明确账户模型，视觉效果比“银行提取现金”更直观。

拍摄：

1. 三步聚光灯中的1—2步；
2. 选择关卡；
3. 选择“资产与负债同增”；
4. 提交；
5. 等待模型落下；
6. 停留3秒展示平衡结果。

可以额外录一条错误选择导致天平倾斜，后期只保留1—2秒。

## 第5段：双主体关系与手势（建议40秒）

优先选择：

```text
押金支付与退还
```

拍摄：

1. 学生方视角；
2. 平台方视角；
3. 权利与义务形成阶段；
4. 打开手势闯关；
5. 展示规则：☝左、✌右、👍是、✊否；
6. 完成“谁拥有返还权”；
7. 完成“谁承担退还义务”；
8. 展示按钮备选。

手势识别最多尝试两次。第二次仍失败就使用按钮备选，后期不要保留失败等待。

## 第6段：教师端总览与认知地图（建议40秒）

拍摄：

1. 教师端顶部洞察；
2. “演示班样例指标”字样；
3. 学生轨迹；
4. 班级认知地图；
5. 双主体关系数据；
6. 3D等式数据。

不要逐个讲完所有图表，只选最能证明“过程评价”的两个图表。

## 第7段：人机协同复核（建议40秒）

拍摄完整闭环：

```text
AI发现问题
→教师填写意见
→退回学生
→学生重新提交
→教师确认通过
```

如果角色切换耗时，分别在两个浏览器录制，再后期拼接。

## 第8段：AI备课与总结（建议35秒）

拍摄：

1. 选择班级；
2. 选择主题和课型；
3. 生成方案；
4. 展示学情依据；
5. 展示内部资源推荐；
6. 健康检查或Mock/Online状态；
7. 结束页。

AI生成结果只展示关键部分，不要从头滚到尾。

# 六、旁白录制方法

## 1. 分段录制

按照8个画面段落分别录音：

```text
V01_教学问题.wav
V02_作品定位.wav
V03_核心闭环.wav
V04_3D等式.wav
V05_双主体手势.wav
V06_教师数据.wav
V07_人机复核.wav
V08_总结.wav
```

## 2. 朗读要求

- 不要像念文件；
- 每句话只强调一个重点；
- 专业术语读完整；
- DeepSeek可读作“深度求索”或“DeepSeek”，全片统一；
- SQLite可不读英文，直接说“本机数据库”；
- 不要频繁说“然后”“接下来”“大家可以看到”。

## 3. 必须说出的四句话

1. “学生必须先完成首次判断，AI才会进行追问和反馈。”
2. “确定性问题由规则校验，开放表达由大模型辅助分析。”
3. “低置信度和规则冲突进入教师复核，最终评价权由教师掌握。”
4. “画面中的百分比为演示班样例指标，不作为真实教学效果结论。”

# 七、剪辑与字幕

## 1. 剪辑软件

可使用：

- 剪映专业版；
- Premiere Pro；
- DaVinci Resolve。

选择自己最熟悉的软件，不要为本次比赛临时学习复杂工具。

## 2. 字幕规范

建议：

```text
字体：思源黑体/微软雅黑
字号：1080p下至少42—50px
颜色：白色
描边：深色2—3px
位置：距底部安全区80—120px
每行：不超过22个汉字
最多：2行
```

重要术语可使用统一强调色：

- 首次判断：蓝色；
- AI追问：紫色；
- 学生订正：绿色；
- 教师复核：橙色。

## 3. 局部放大

适合放大的位置：

- 输入质量检查；
- 首次判断与订正对照；
- 3D账户牌；
- 权利和义务；
- 教师退回按钮；
- 演示班样例指标。

放大幅度建议110%—135%，不要突然放大到200%。

## 4. 转场

使用简单淡入淡出或直接切换。不要使用炫目的旋转、爆炸、故障转场。

## 5. AI等待处理

可以：

- 删除无内容等待；
- 将等待过程加速2—4倍；
- 保留“正在分析”0.5—1秒证明真实调用。

不可以：

- 修改AI原始反馈含义；
- 拼接不存在的结果；
- 把Mock结果说成在线模型实时结果。

# 八、成片技术检查

导出第一版后完整观看三遍。

## 第1遍：只看画面

- 是否有隐私信息；
- 是否有弹窗和通知；
- 鼠标是否乱晃；
- 文字是否可读；
- 聚光灯是否高亮正确区域；
- 是否出现加载失败、空白或按钮无响应；
- 是否错误展示应用B。

## 第2遍：只听声音

- 是否有爆音、喷麦、底噪；
- 旁白是否被音乐覆盖；
- 专业术语是否读错；
- 是否出现效果夸大；
- 是否明确样例数据口径；
- 是否明确教师最终评价权。

## 第3遍：按评委视角看逻辑

评委能否在5分钟内回答：

1. 作品解决什么真实教学问题？
2. 为什么不是普通记账软件？
3. AI具体做什么、不做什么？
4. 学生是否先思考？
5. 教师如何看到学习过程？
6. 3D和手势为什么有教学意义？
7. 软件是否可以独立安装运行？
8. 数据和隐私是否安全？

有任何一题回答不出来，就需要调整画面或旁白。

# 九、最终文件检查

建议文件名：

```text
大学生生活记账与会计AI伴学软件_演示视频.mp4
```

最终确认：

- MP4可正常打开；
- H.264编码；
- 1920×1080；
- 30fps；
- 时长符合平台要求；
- 文件大小符合上传限制；
- 从头到尾音画同步；
- 最后3秒显示作品名称；

- 无真实学生隐私；

```text
本机硬盘
U盘或移动硬盘
```

条件允许再保存一份到个人云盘。
